## Docker Desktop blocker

Docker Desktop repeatedly fails before its engine starts while renaming `%LOCALAPPDATA%\Docker\run\sailor-ingest.sock` to a `.stale` path. Windows reports “The file cannot be accessed by the system” (error 1920). The path still exists as a reparse point, and `fsutil reparsepoint query` also returned error 1920. These observations explain why the same startup step fails on every launch; they do not establish why Windows made that socket inaccessible. Factory reset did not resolve it. The attempted targeted stop/remove action was rejected by automatic tool review as **“blocked by policy”** with no more specific reason. No further filesystem repair was attempted. Docker's [troubleshooting guide](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/) describes gathering diagnostics from the error dialog or `docker desktop diagnose` and submitting a diagnostic ID with a community issue or support request.
